# SEO & favicon runbook

Site root: `https://marijapopeska.com`

## Where things live

| Thing | Path |
|---|---|
| Favicon assets | `assets/img/favicon/` |
| Web app manifest | `assets/img/favicon/site.webmanifest` |
| Crawler rules | `robots.txt` |
| Sitemap | `sitemap.xml` |

Favicon set was generated by RealFaviconGenerator: `favicon.ico`, `favicon.svg`,
`favicon-96x96.png`, `apple-touch-icon.png` (180x180), and the 192/512 PNGs used
by the manifest.

## Adding a new page

Copy the `<head>` of an existing case study (e.g. `pages/project-1.html`) and update:

1. `<title>` — `<Page name> | Marija Popeska`, keep under ~60 characters.
2. `<meta name="description">` — 150-160 characters, unique per page. Never reuse.
3. `<link rel="canonical">` — absolute URL, must match the real deployed path.
4. Favicon block — `../assets/img/favicon/...` from `pages/`, `./assets/...` from root.
5. Open Graph — `og:url`, `og:title`, `og:description`, `og:image` (**absolute URL**,
   relative paths do not work for social scrapers), plus `og:image:width` /
   `og:image:height` matching the file's **real** pixel dimensions.
6. Twitter card — mirrors the OG values.
7. JSON-LD — `WebPage` + `CreativeWork` + `Person` + `BreadcrumbList`. Keep the
   `@id` anchors (`#person`, `#website`) identical across pages so the graph links up.

Then add the page to `sitemap.xml` and bump its `<lastmod>`.

To check real image dimensions on Windows:

```powershell
Add-Type -AssemblyName System.Drawing
$i=[System.Drawing.Image]::FromFile((Resolve-Path 'assets/img/foo.jpg')); "$($i.Width)x$($i.Height)"
```

## Gotchas

- **Never** add `<meta name="rating" content="adult">`. It used to be on every page
  and tells search engines to treat the portfolio as adult content, which gets it
  filtered out of SafeSearch results. It has been removed.
- Do not duplicate `og:*` tags or mix `name=` with `property=` on the same tag.
  Scrapers pick one at random and the result is unpredictable.
- `og:image` dimensions must be truthful. The old tags all claimed 1200x627 and
  not one image actually was.
- Logo `<img>` needs a real `alt` — it sits inside a link with no text, so an empty
  alt leaves that link with no accessible name.
- Icon-only social links need `aria-label`; the boxicons `<i>` contributes no text.
- Manifest `icons[].src` resolves relative to the manifest file, so bare filenames
  are correct there. `start_url` / `scope` are site-root absolute (`/`) and assume
  deployment at the domain root, not a GitHub Pages subpath.

## Verifying

```bash
# JSON-LD parses on every page
node -e 'const fs=require("fs");for(const f of ["index.html",...fs.readdirSync("pages").map(x=>"pages/"+x)]){for(const m of fs.readFileSync(f,"utf8").matchAll(/<script type="application\/ld\+json">([\s\S]*?)<\/script>/g)){try{JSON.parse(m[1]);console.log("OK",f)}catch(e){console.log("FAIL",f,e.message)}}}'
```
